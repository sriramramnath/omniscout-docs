Browser memory is a local vector index over pages you've visited and notes you've written. Store now, recall semantically later — no LLM calls.

## Remember a page

```bash
omniscout remember https://example.com/blog/post
```

`remember` visits the URL, extracts its content, and stores it in `memory.sqlite`. Search it later with `memory`:

```bash
omniscout memory "neural networks in production"
```

`memory` ranks stored pages by semantic similarity to your query, so paraphrases match — you don't need the exact title or URL.

## Search your own memory first

The `search` command can target memory instead of the web:

```bash
omniscout search "query" --source memory
```

Useful in agents: check what you've already seen (`--source memory`) before spending time on a fresh web search.

## Manage the corpus

`memory` is a command group, not just a query:

```bash
omniscout memory "query"     # semantic search over remembered pages
omniscout memory list        # list records
omniscout memory show <id>   # show one record
omniscout memory note "idea: compare rerankers"   # standalone note
omniscout memory delete <id> # delete records
omniscout memory stats        # corpus statistics
omniscout memory clear        # wipe the entire corpus
```

Attach a note to the active page (or write a standalone one) with `memory note` — notes are indexed too, so decisions and context resurface in later searches.

## The local index

Related local-index commands:

```bash
omniscout index ...          # manage the local search index (re-index, query cache)
omniscout crawl ...          # run and inspect local crawl jobs
omniscout extract-jobs ...   # inspect background extract jobs
```

Memory (`memory.sqlite`), the vector index (`qdrant/`), and the page cache (`cache/pages/`) all live in the data dir — see [Configuration](/docs/cli/configuration). They never leave your machine; the only outbound traffic is searches you run and URLs you fetch.
